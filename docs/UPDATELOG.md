## 维护注意事项（做 update 时必须遵守）

> 本区为**维护流程规则**（更新 skill 时的注意事项），不属于分析框架内容——**不得写入 SKILL.md**。

**Plan 自审协议**：生成的任何 plan（修复/重构/新机制计划）必须附带自审，五项审视发现必须修订进 plan 后方可实施：
1. **竞争性假说**：每个问题定义是否有替代解释？被选解释的排除依据是什么？
2. **二阶效应**：方案实施后的反噬是什么？（表演性执行/变相回滚/代理指标游戏化）
3. **物理锚定**：方案中的数字/约束是否有依据？代理指标（行数/数量）是否被声明为代理？
4. **博弈完整性**：执行者是谁？其激励是否与方案目标一致？不一致时如何绑定？
5. **前提验证**：方案的隐含前提是什么？是否需最小验证前置（先验证再全面落地）？

自审结论随 plan 一并交付，标注"Plan 自审：通过/修订后通过/不通过"。

**核心框架体量上限**：`SKILL.md` 行数是**代理指标**，不是目标本身——机制完整性优先：
- 冻结上限 **500 行**（Claude 官方 skill 规范；当前 216 行）：超限触发"精简 + 淘汰评估"（先评估冗余表述；无冗余可删时按框架自我约束条款评估机制淘汰）。
- 精简只允许删除"表述冗余"，**禁止删除机制本体**（检查项/协议/质量标准）。
- 每次 update 后核对行数；README 行号声明同步更新。

### v1.9.0 — 机制体系整合 + 行为实验精简 — 2026-08-05~08-08

**定位**：主版本（整合 + 重构）。触发背景：1.8.0 期间累积 15 个补充，主文件机制数超过 40 项"必须执行"——超出单次分析可靠执行容量（5-9 项），"知识-执行分离"根因从纪律问题变为容量问题。

**v1.9.0 补充③（对抗式交互升级，2026-08-08，参照 grill-me 等同类 skill 分析）**：攻击循环协议升级——①**一句话核心**（"先暴露你的默认立场，再找反方攻击它，记录哪些被推翻、哪些幸存"——记忆锚点）；②**强度可调**（默认全力 / "轻一点"降澄清型 / "狠一点"升摧毁型——借鉴 devils-advocate 强度分级但拒绝档位玩具化）；③**记录 vs 确认区分**（低风险攻击记入修订痕迹，高风险推翻必须用户确认——拒绝 challenge 式"只暴露不可逆"因为修订痕迹是唯一可验证产物）；④**适配用户状态**（新手澄清概念、专家深挖假设——拒绝独立校准阶段避免打断流程）；⑤**对抗审查入口**（用户说"泼冷水/挑刺/反驳我/压力测试"时攻击循环升级为主流程，逐问+推荐答案——借鉴 grill-me 交互模式，但仅用户显式触发，不污染常规分析触发）。
