## 维护注意事项（做 update 时必须遵守）

> 本区为**维护流程规则**（更新 skill 时的注意事项），不属于分析框架内容——**不得写入 SKILL.md**（防止维护流程规则污染执行层）。

**Plan 自审协议（v1.8.0 补充确立）**：生成的任何 plan（修复/重构/新机制计划）必须附带自审，五项审视发现必须修订进 plan 后方可实施：
1. **竞争性假说**：每个问题定义是否有替代解释？被选解释的排除依据是什么？
2. **二阶效应**：方案实施后的反噬是什么？（表演性执行/变相回滚/代理指标游戏化）
3. **物理锚定**：方案中的数字/约束是否有依据？代理指标（行数/数量）是否被声明为代理？
4. **博弈完整性**：执行者是谁？其激励是否与方案目标一致？不一致时如何绑定？（执行者=被约束者的场景必须显式分析）
5. **前提验证**：方案的隐含前提是什么？是否需最小验证前置（先验证再全面落地）？

自审结论随 plan 一并交付，标注"Plan 自审：通过/修订后通过/不通过"。

**核心框架体量上限（v1.8.0 补充确立）**：`SKILL.md` 行数是**代理指标**，不是目标本身——机制完整性优先：
- 冻结上限 **650 行**（当前 607 行）：超限触发"精简 + 淘汰评估"（先评估冗余表述；无冗余可删时按框架自我约束条款评估机制淘汰），而非单纯删行凑数。
- 理想目标 600 行：精简只允许删除"表述冗余"（重复段落/解释性文字），**禁止删除机制本体**（检查项/协议/质量标准）。
- 每次 update 后核对行数；README×2 的行号声明同步更新。

### v1.9.0 补充② — 攻击循环协议（原"元认知前置协议"经五轮对攻修订） — 2026-08-07

**定位**：1.9.0 内补充（版本内补充编号惯例）。触发背景：分析者在单一叙事环境（官方口径/媒体共识/权威声明）下的先天倾向（权威认可/默认叙事锚定）在分析开始前即已形成，而现有对抗机制全部位于分析流程后半段——事后检验无法阻止起点锚定。

**五轮对攻过程（重要元记录）**：
- Plan 1：提出"元认知前置协议"（先验声明/竞争假说前置/反证前置，第一层每轮必跑）——已执行提交
- Plan 2（攻击）：内省路径不可靠（Nisbett & Wilson）；过度泛化（硬数据免疫论不成立）；容量假发票（三项按一项计）；位置性标注例行化；触发条件自指悖论；漏信息层
- Plan 3（攻击）：硬数据权威性可被制造（OpenCode 统计口径/厂商自报/CAISI 官方立场）；信源多样是伪解法（受控反对/解读仍被先验塑造）；证伪条件选择本身依赖内省（换位内省）；证伪可被叙事吸收；权重判断不适用单一证伪条件
- Plan 4（攻击）：证伪条件无人跟踪（输出形态≠认知过程）；证伪绑定强度的选择即先验体现；"全有或全无"谬误；多先验交叉在单执行者系统不可实现且无收敛机制
- Plan 5（攻击·收束）：多先验不存在（模拟对立立场仍是自我指涉）；外部视角同样被单一叙事塑造；元发现——五轮对话中唯一实证起效的是"来自不同立场的攻击"本身（用户质疑真实改变了分析者先验），而非任何静态条款

### 关键优化逻辑（设计哲学）

1. **从"禁止"到"允许例外"**：优秀规则系统不是 cover everything——是"cover the common case + allow principled exceptions"（豁免三条件/聚焦深度豁免的由来）
2. **从"事后修补"到"事前预防"**：通过案例模式识别建立"事前防呆"机制（Anti-inertia 基于 3 次 Economics-only 模式、批处理协议基于 40 条热搜经验、跨域扫描基于 AI 伴侣禁令遗漏）
3. **从"完整输出"到"按需输出"**：分析完整性 ≠ 输出完整性——用户要的是"刚好够用"（三级降级/摘要分离/lite 的由来）
4. **从"工具命名"到"工具区分"**：工具池质量不取决于数量，取决于区分度——"不能一句话说清何时用 A 不用 B，工具就只是命名"（反身性/反馈/路径依赖区分测试的由来）

### 技能定位

强于权力分析与文化批判（对比麦肯锡 MECE：弱于结构化分解）；强于个体体验与情感维度（对比系统动力学：弱于定量反馈环路）；保持 actionable 输出承诺（对比纯批判理论：不以"拆解一切"为终点）。
