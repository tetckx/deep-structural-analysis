# 策略互动矩阵 (Strategic Interaction Matrix)

> 工具完整文档 · 与 SKILL.md Phase 4 工具池 G 类对应
> 版本归属：主版本链（随包同步，不设独立版本号）

## 定义

*博弈论分析框架，聚焦"等待博弈/先手-后手/信号博弈"。* 起源：博弈论中的先行者优势（first-mover advantage）、等待博弈（waiting game）、囚徒困境与信号传递模型。陷阱：把一切互动都框成博弈——不是所有互动都是策略性的，部分互动是惯性或适配的结果。用它来问"理性玩家在此结构下会怎么选择"，不要用它来假设"每个玩家都是完全理性的"。

## 核心三问

1. **等待博弈检测**：是否存在"先下注者承担验证成本、后跟进者搭便车"的结构？如果是——谁会先动？什么外部力量（政策、危机、灯塔案例）能打破死锁？
2. **先手-后手评估**：谁是先手？先手的优势（定义标准/占领心智/积累数据）与成本（验证风险/沉没成本）哪个更大？后手是否在等待先手失败后收割？
3. **信号博弈识别**：玩家的公开动作（发布、定价、沉默）是能力信号还是虚张声势？信号成本与信号可信度是否匹配？（低成本信号不可信——只有高成本信号才可能是真实的）

## 应用要点

- 与 MLSD 的区别：MLSD 解码"信息"的博弈结构；策略互动矩阵分析"行动"的博弈结构（谁在等、谁在动、为什么）
- 与 Incentive Mapping 的区别：激励映射看"结构内的收益分配"；策略互动矩阵看"结构本身如何被玩家博弈改变"
- **沉默也是行动**：在等待博弈中，所有玩家同时沉默=死锁；单一玩家先动=破局；观察"谁在动、谁在等"比观察"谁在说什么"更重要

## 披露博弈子模式（v1.6.1 机制）

当分析对象涉及敏感事件（安全事故/丑闻/风险暴露）时，玩家间存在"披露竞争"——先披露者定义叙事框架，后披露者只能防守。检测要点：

- 是否存在"竞相披露"动态（一家披露后，其他玩家短期跟进）？
- 披露内容是否带有"区分叙事"（"我们的事件与XX不同"）——这是为定义权竞争铺路？
- 披露时机（谁先、间隔多久）本身就是信号——**行动时序 > 文本内容**
- 子模式结论：披露博弈的均衡通常是"竞相披露"（不披露被扒出的损失 > 披露的声誉损失）；先披露者获得叙事定义权，但承担"被审查得更严"的风险

## 多玩家降级协议（v1.6.1 机制，玩家数 >3 时强制）

1. 放弃精确预测（谁何时做什么），改输出三个方向性维度：**均衡方向**（系统会往哪走：披露竞争/等待死锁/竞相加速）、**触发条件清单**（哪些事件会改变博弈结构：监管出台/第三方复核/新事故）、**关键信号**（观察什么来判断博弈走向：披露间隔/措辞变化/行动时点）
2. 将玩家合并为"阵营"（如：前沿实验室阵营/监管者阵营/第三方机构阵营）再分析——阵营内玩家视作同质
3. 降级必须在输出中显式声明："玩家数>3，博弈推演已降级为方向判断（均衡方向+触发条件+关键信号）"
4. 触发条件清单应优先于时间点预测——**博弈论告诉你"会往哪走"，不告诉你"什么时候到"；用"什么事件会触发"替代"何时会发生"**

## 已知局限

1. 假设玩家理性——非理性玩家（受情绪/意识形态驱动）会让博弈推演失真
2. 无法预测均衡的到达时间——博弈论告诉你"会往哪走"，不告诉你"什么时候到"
3. 多玩家博弈的可解性骤降——超过3个玩家时，策略推演从"预测"降级为"方向判断"
4. 忽略博弈外力量——政策干预、黑天鹅事件、技术突变可以瞬间改变博弈结构

## 校准检查

拿掉这个工具，用常识看——这个场景中玩家的行为是否可以用"惯性/资源约束/组织文化"充分解释？如果可以——不是博弈，是惯性。只有当玩家的行为显示出"对他人行为的策略性预期"时，博弈框架才在工作。**额外检查——如果你发现每个场景都是"等待博弈"，你可能在过度拟合：不是所有停滞都是策略性等待，有些只是单纯的慢。**
