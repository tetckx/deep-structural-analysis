# Cookbook：端到端使用示例

> 本示例展示一次 Standard 深度分析的真实产出形态（含 Phase 1.5 立场征集与攻击循环）。
> 完整实战案例参考 docs/case-test-archive.md（极限测试历史）。

## 场景示例："分析某公司涨价后的用户分层"

### 产出形态（Part A 执行摘要）

```
深度声明：Standard · 复杂度域 Complex

【暴露靶子】默认立场："涨价必然导致用户流失"（待攻击——请用户挑战）
【立场征集】用户立场：开发者（"涨价后我该不该留下"）——真实立场
   AI 候选（组织工具，非发现）：资本/竞品/监管/旁观者
【核心发现】涨价结构（输出 4.5x/缓存 12.1x）与用户深度分层精确对齐：
   轻度用户（直调）被清场——中层（权衡）被 harness 缓存经济争取——
   核心（生态用户）被锁定——"用户流失"叙事是单立场误读
【多镜共识】经济学（价格弹性）/ 制度（生态锁定）/ 技术（缓存率 97%）
【置信度】中——价格结构是事实（高），分层意图是解释（中）
【修订痕迹】反证"涨价=定价自杀"被评估：缓存价绝对低（$0.044）+
   97% 命中率下真实成本 4.7x 而非 12x → "自杀"降级为"生态税"
【分层影响】系统（行业价格战停火）/ 制度（生态标准）/ 个体（开发者账单）
【待验证信号】涨价生效后 OpenCode token 份额（判决性）；DSH 缓存率保持
【分析边界】不覆盖：DS 内部意图（不可验证）；地缘政策影响
【盲点】融资条款不可见；中度用户的真实迁移数据未获

【邀请真实攻击】"我的默认立场是 X，最可能被推翻的地方是 Y——请攻击"
```

### 使用要点

1. **立场征集不可跳过**：分析前先问用户"你站在哪、关心什么、看到什么我看不到的"——用户立场是发现引擎，AI 候选只是组织工具
2. **攻击执行者是用户**：AI 不模拟攻击——交付时显式邀请真实攻击；无用户参与时标注"发现能力受限"
3. **不可通约性是入口**：不同立场看到的东西互相矛盾但各自为真——呈现张力，不合成"完整真相"——判断权交还决策者
4. **边界标注**：AI 模拟立场必须标注（"资本立场为模拟视角"）；无用户参与的自动分析降级为视角审计
